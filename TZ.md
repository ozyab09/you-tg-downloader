# Техническое задание: Telegram-бот для скачивания видео с YouTube

## 1. Общее описание

Необходимо разработать Telegram-бота, который принимает от пользователя ссылку на YouTube-видео, предоставляет выбор формата (видео различного качества или аудио), скачивает выбранный контент и отправляет его обратно в чат как файл.

**Ключевые требования:**
- Работа через Telegram Bot API (polling или webhook — на усмотрение исполнителя, приоритет — polling для простоты развёртывания).
- Развёртывание через `docker compose`.
- Конфигурация через переменные окружения (`.env`).
- Все логи — исключительно в `stdout`/`stderr`.
- Доступ только для белого списка Telegram user ID.
- Минимизация дисковых операций: приоритет — потоковая передача из загрузчика в Telegram без полной записи на диск.

---

## 2. Функциональные требования

### 2.1. Приём ссылки
- Бот принимает текстовое сообщение, содержащее ссылку на YouTube (`youtube.com`, `youtu.be`, `m.youtube.com`, `music.youtube.com`).
- Ссылки вне YouTube игнорируются с вежливым сообщением об ошибке.
- Некорректные URL — обрабатываются, пользователь получает сообщение о неверном формате.

### 2.2. Получение информации о видео
- После получения ссылки бот извлекает метаданные через `yt-dlp` (или аналог):
  - название,
  - длительность,
  - доступные форматы (видео + аудио).
- Отображает пользователю inline-клавиатуру с вариантами:

**Видео (с аудиодорожкой, mp4):**
- 360p
- 480p
- 720p (HD)
- 1080p (Full HD)
- 1440p / 4K — если доступны (опционально)

**Аудио:**
- MP3 (128 / 192 / 320 kbps) — на выбор исполнителя, минимум один вариант.

**Дополнительно (опционально):**
- «Лучшее доступное качество».

- Кнопки должны содержать отображаемое качество и скрытый `callback_data` с идентификатором формата `yt-dlp`.
- Если формат недоступен для конкретного видео — он не отображается.

### 2.3. Скачивание и отправка
- После выбора формата бот:
  1. Отправляет сообщение о статусе («Скачиваю…»).
  2. Запускает скачивание выбранного потока.
  3. Передаёт результат в Telegram (`send_video` / `send_audio` / `send_document`).
- **Приоритетная реализация:** потоковая передача без промежуточного файла на диске.
  - Вариант A: pipe из `yt-dlp` в stdin Bot API (через `requests` / `httpx` с `multipart/form-data`).
  - Вариант B: скачивание во временный файл в `/tmp` (или tmpfs) с обязательным удалением сразу после отправки (в `finally`).
- Если размер файла превышает лимит Telegram Bot API (50 МБ для обычных ботов, 2 ГБ для локального Bot API Server) — пользователь получает соответствующее уведомление.
- После успешной отправки временный файл (если использовался) удаляется.

### 2.4. Обработка ошибок
- Скачивание недоступно (приватное видео, регион, возрастное ограничение) → понятное сообщение пользователю.
- Ошибка Telegram API → логирование + сообщение пользователю.
- Таймауты → отмена задачи и уведомление.

### 2.5. Ограничение доступа
- Проверка `user_id` на каждом входящем апдейте.
- Если ID отсутствует в белом списке — бот игнорирует сообщение (без ответа) и логирует попытку доступа на уровне `WARNING`.
- Проверка выполняется как для сообщений, так и для callback-запросов.

### 2.6. Ограничения (опционально, рекомендуется)
- Максимальная длительность видео (например, 30 минут) — настраивается через ENV.
- Максимальный размер скачиваемого файла — настраивается через ENV.
- Одновременная обработка запросов от одного пользователя — не более 1.

## 3. Технические требования

### 3.1. Стек
- Язык: **Python 3.11+** (рекомендуется) либо Node.js — на усмотрение исполнителя, с обоснованием.
- Библиотеки:
  - Telegram: `aiogram 3.x` / `python-telegram-bot 21+` / `pyrogram`.
  - Скачивание: `yt-dlp` (обязательно).
  - HTTP-клиент: `httpx` / `aiohttp`.
- FFmpeg — для объединения видео+аудио и конвертации в MP3 (устанавливается в образ).

### 3.2. Архитектура
- Асинхронная обработка (asyncio).
- Очередь/семафор для ограничения параллельных скачиваний.
- Модульная структура:
  ```
  app/
    ├── bot/           # хендлеры, клавиатуры
    ├── downloader/    # обёртка над yt-dlp
    ├── config/        # загрузка ENV
    ├── utils/         # логирование, форматирование
    └── main.py
  ```

### 3.3. Docker и docker compose
- `Dockerfile` на базе `python:3.11-slim` (или alpine с установленным ffmpeg).
- В образ устанавливаются `ffmpeg` и зависимости Python.
- `docker-compose.yml`:
  - сервис `bot`,
  - `env_file: .env`,
  - `restart: unless-stopped`,
  - проброс логов в stdout (`logging` без файловых хендлеров).
- Пример `.env`:
  ```env
  TELEGRAM_BOT_TOKEN=123456:ABC...
  ALLOWED_USER_IDS=11111111,22222222
  MAX_FILE_SIZE_MB=50
  MAX_VIDEO_DURATION_MIN=30
  LOG_LEVEL=INFO
  ```
- `.env.example` должен присутствовать в репозитории.
- `.gitignore` исключает `.env`.

### 3.4. Логирование
- Только `stdout`/`stderr` (никаких файлов внутри контейнера).
- Формат: `%(asctime)s | %(levelname)s | %(name)s | %(message)s`.
- Уровень настраивается через `LOG_LEVEL`.
- Логируются: старт/остановка, входящие запросы (user_id, URL, выбранный формат), ошибки скачивания, ошибки Telegram API, отклонённые попытки доступа.

### 3.5. Безопасность
- Токен и ID пользователей — только через ENV, не хардкодятся.
- Валидация URL (regex + `yt-dlp` `extract_info`).
- Защита от SSRF/подмены домена (проверка списка разрешённых доменов YouTube).
- Ограничение размера загружаемых данных.

## 4. UX-требования

- Сообщения пользователю — на русском языке (либо i18n — опционально).
- Inline-клавиатура с выбором качества, аккуратно сгруппированная:
  ```
  [ 360p ] [ 480p ] [ 720p ]
  [ 1080p ] [ Best ]
  [ MP3 128 ] [ MP3 320 ]
  ```
- Индикация прогресса (при возможности — редактирование сообщения «Скачано X%»).
- Чёткие сообщения об ошибках без технических деталей.

## 5. Критерии готовности (Definition of Done)

1. Проект собирается и запускается командой `docker compose up -d`.
2. Бот принимает YouTube-ссылку от авторизованного пользователя, отображает варианты форматов, скачивает и отправляет файл.
3. Пользователь вне белого списка не получает ответа.
4. После отправки файла временные данные на диске не остаются (`ls /tmp` чист, если использовалась диска-реализация).
5. Все логи видны в `docker compose logs -f bot`.
6. README содержит:
   - инструкцию по установке и запуску,
   - описание переменных окружения,
   - ограничения Telegram Bot API по размеру файла,
   - пример `.env`.
7. Код соответствует PEP 8 (для Python), присутствует базовая типизация.
